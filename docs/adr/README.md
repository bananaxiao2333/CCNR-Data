# 架构决策记录（ADR）

记录**重要且不易回退**的决策：为什么这么选、放弃了什么、以后怎么推翻。

## 什么时候写 ADR

- 改变服务定位或职责边界（例如「CCNR-Data 从数据存储变成控制面」）
- 替换持久化方式、协议、迁移机制
- 引入跨仓库的组件（代理插件、身份桥）
- 改变门禁或工程规范

小改动（加一个 RPC、修一个 bug）**不需要** ADR。

## 命名与格式

`NNNN-短横线标题.md`，四位编号，永不复用。模板见 [template.md](template.md)。

状态取值：`提议` / `已接受` / `已废弃`（被 XXX 取代） / `已取代`。
