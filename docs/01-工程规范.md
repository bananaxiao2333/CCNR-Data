# 01 · 工程规范

## 1. 分层与职责

```
scripts/          一次性入口：生成、冒烟、压测、门禁
tests/            自动化测试（一律走真实 gRPC 通道）
proto/            协议契约（唯一权威）
src/moddata/      生成桩（禁止手改）
src/ccnr_data/
    config.py     配置解析与范围校验（只读环境/参数，不读文件、不连库）
    clock.py      时间基准（统一 UTC epoch 毫秒）
    errors.py     领域异常 → gRPC 状态码
    validation.py 信任边界校验（所有入参的唯一入口）
    db.py         连接、事务边界、模式 bootstrap
    schema.sql    表结构
    repo.py       纯 SQL 数据访问（不写业务规则）
    service.py    gRPC 实现：校验 → 规则 → 调 repo → 组响应
    retention.py  日志轮换
    server.py     服务装配（业务 + 健康检查 + 反射）
    __main__.py   CLI
```

**依赖方向单向向下**，不允许反向 import：

```
server → service → { validation, repo, retention } → db / clock / errors
config / clock / errors 不依赖任何业务模块
```

**判定标准**：`service.py` 里出现 SQL 字符串、或 `repo.py` 里出现 `if` 判断业务规则，都是分层破了。

## 2. 硬性禁止

| 禁止 | 原因 |
|---|---|
| 占位实现（`pass` / `NotImplementedError` / 返回假数据的桩） | 占位代码会被当成已完成，问题推迟到线上才暴露。功能没做完就不写这个 RPC |
| 未使用的字段 / 参数 / 配置项 | 是"以后可能要用"的假需求，会一直留在契约里 |
| 手改 `src/moddata/` | 生成物，改了下一次生成就被覆盖；门禁会检测漂移 |
| 测试里 mock 掉序列化 / 事务 / 状态码 | 被 mock 掉的正是最容易错的一层 |
| 静默钳制越界配置 | "我配了 50ms" 变成"实际 100ms"，排障时毫无线索。越界一律启动失败 |
| 同一原因在不同 RPC 返回不同错误码 | 客户端没法写统一重试策略。状态码只在 `errors.py` 定义、只在 `service._handle` 翻译 |

## 3. 命名与风格

- Python 3.12+，`from __future__ import annotations`，全量类型标注。
- 行宽 110（`ruff`），`spotless` 对应物就是 `ruff format`，**提交前必须收敛**。
- 每个 `.py` 首行许可头：

  ```python
  # Copyright (c) 2026 CCNR
  # SPDX-License-Identifier: MIT
  ```

- 公开函数/模块有 docstring，**写"为什么"不写"做什么"**。`# 递增版本号` 这种注释直接删。
- 领域术语用中文（事件 / 结算 / 幂等 / 轮换），代码标识符用英文。
- 刻意的让步必须留痕迹：`# ponytail: <天花板是什么>，<什么时候该升级>`。

## 4. 门禁

`./scripts/check.sh` 一条命令跑全部；CI（`.github/workflows/ci.yml`）跑的是同一份。

| # | 门禁 | 挡住什么 |
|---|------|---------|
| 1 | `compileall` | 语法错、编码问题 |
| 2 | 许可头检查 | 漏头文件 |
| 3 | `ruff format --check` | 风格漂移 |
| 4 | `ruff check` | 未用导入/变量、可读性陷阱（`E F W I UP B SIM C4 RET PTH`） |
| 5 | `mypy`（strict） | 类型漏洞；`grpc` / `protobuf` 无 py.typed，按未类型化依赖处理 |
| 6 | `gen_proto.py --check` | 改了 proto 没重新生成、或手改了生成物 |
| 7 | `pytest` | 行为回归 |

**不许"CI 上另有一套"**：本地跑不过的，CI 上一定过不了；反之亦然。

## 5. 测试要求

- **走真实 gRPC 通道**（`conftest.py` 起真实 server + 真实 channel），不 mock。
- 端口一律 `127.0.0.1:0`，由内核分配，避免并发/CI 端口冲突。
- `pytest-timeout = 60`：流式订阅与线程池测试写错就是挂死，超时把它变成可读的失败。
- 每个不变量至少一条测试：

  | 不变量 | 测试 |
  |---|---|
  | 重放不重复落账 | `test_idempotency.py::test_replay_returns_same_response_and_applies_once` |
  | 并发同键只生效一次 | `test_idempotency.py::test_concurrent_replay_applies_exactly_once` |
  | 同键不同载荷报错 | `test_idempotency.py::test_same_key_different_payload_rejected` |
  | 明细合计 = gain | `test_settlement.py::test_invalid_settlements_rejected` |
  | 权威端覆盖本地值并回报差异 | `test_settlement.py::test_divergence_reported_and_authority_wins` |
  | 策略冻结挡写不挡读 | `test_role_config.py::test_frozen_policy_denies_changes` |
  | 轮换只删过期的 | `test_retention.py::test_purge_removes_only_expired` |
  | 业务表永不被清 | `test_retention.py::test_business_tables_are_never_purged` |
  | 模式版本不符拒绝启动 | `test_server.py::test_schema_version_mismatch_refuses_to_start` |

- 非平凡逻辑（分支/循环/解析）必须留一条能跑的检查。**测试也是代码**，同样禁止占位。

## 6. 文档规范

- 每个 `docs/NN-*.md` 只回答一类问题，标题写"解决什么问题"而不是"介绍什么"。
- 数字必须是**实测**的，并写清测量口径（见 [docs/05](05-部署与运维.md) §4）。
- 与方案草图不一致的地方，必须显式列出并给理由（见 [docs/02](02-协议契约.md) §5），不允许悄悄改掉。
