# 06 · 控制面与统计

本篇回答三个问题：**CCNR-Data 为什么多了控制面、它对外承诺什么、出故障时谁兜底**。
数据面（模组上报）仍见 [docs/02](02-协议契约.md)，表结构见 [docs/03](03-数据模型.md)。

## 1. 定位

```
玩家 ──► Velocity + ccnr-control ──gRPC(control.v1)──► CCNR-Data
                │  准入 / 遥测                       ├─ ModDataService（既有，不动）
CCNR-RP 模组 ───┼──gRPC(moddata.v1)─────────────────►├─ ControlService（新）
Bot ────────────┴──gRPC(control.v1)─────────────────►├─ Casdoor 适配器（出站 REST）
                                                     └─ SQLite（SQLAlchemy / Alembic）
```

边界：

- Casdoor 是唯一身份源；本服务只存投影（`player_identities`），**不读 Casdoor 库**。
- 本服务**不调用 Gate**：连接、转服、踢人是代理/模组的动作，控制面只回答「能不能进」与记录「发生了什么」。
- 本期不接 KubeMCGate；`server_id` 就是 Velocity 的服务器名。

## 2. 契约（`control.v1`）

权威定义在 `proto/control/v1/control.proto`。

| RPC | 幂等 | 用途 |
| --- | --- | --- |
| `AuthorizePlayer` | 读 | 登录准入；返回 allow/deny、原因、角色、缓存 TTL |
| `ReportProxyEvent` | 是 | 会话开始 / 心跳 / 转服 / 结束 / 登录失败 |
| `ListOnlinePlayers` | 读 | 在线列表（可按 server 过滤） |
| `GetPlayerPlaytime` | 读 | 按时段查时长与会话数 |
| `GetProxyStats` | 读 | 独立玩家 / 会话 / 总时长 / 登录失败 / 分服 |
| `ResolvePlayer` | 读 | UUID / 用户名 / Casdoor ID 互查 |
| `BindPlayerIdentity` | 是 | 写身份投影（管理、bot、皮肤回调共用） |
| `SetAccessRule` / `ListAccessRules` / `DeleteAccessRule` | 是/读/是 | 封禁与白名单 |
| `SetAccessPolicy` / `ListAccessPolicies` | 是/读 | 作用域准入模式（open / whitelist） |
| `BeginDeviceLogin` / `GetDeviceLoginStatus` | 是/读 | CCNR Pass 设备码登录；服务端后台轮询，成功后写身份投影 |
| `GetAccountLink` / `BindAccountLink` / `DeleteAccountLink` | 读/是/是 | 平台账号（QQ 等）↔ Casdoor 绑定；bot 不再本地存绑定 |

约定：

- `AuthorizePlayer` **不写库**；拒绝由插件上报 `LOGIN_DENIED`，避免登录风暴写放大。
- 所有写 RPC 带 `request_id`，复用 `idempotency` 表，幂等行与业务行同事务。
- `occurred_at` 由客户端给，服务端夹在 `[now-24h, now+5m]`；另存 `received_at` 诊断时钟偏移。

## 3. 登录与准入

代理不信任"玩家说自己是某个名字"：连接先进 limbo（`auth` 服），插件调
`BeginDeviceLogin` 拿到 `user_code` 与验证地址；玩家在 CCNR Pass 完成登录后，
`DeviceLoginPoller` 用 device code 换 token，解析 `owner/preferred_username`，
写入 `player_identities`（`source=PASS`）。插件确认 **这条连接** 已通过后，
才把它送到 `lobby` 并调 `AuthorizePlayer` 做封禁/角色检查。

因此：**静态绑定不再是准入依据；每次连接都必须完成一次 Pass 授权。**

## 4. 准入策略

判定顺序固定（先命中先返回）：

1. 未过期 `DENY` 规则（UUID / 用户名 / Casdoor ID，global 或 server）→ `BANNED`；
2. scope 的 `access_policies` 为 `whitelist` 且没有 `ALLOW` 规则 → `WHITELIST_ONLY`
   （scope 未配置时回退到全局空串；两者都没有记录按 `open` 处理）；
3. 身份解析失败 → `NOT_LINKED`（提示先绑定 MC 账号）；
4. Casdoor 用户不存在 / 邮箱未验证 / 禁用 → `EMAIL_UNVERIFIED` / `CASDOOR_UNAVAILABLE`；
5. 角色 ACL 不匹配 → `ROLE_DENIED`；
6. 放行。

缓存与降级：

| 层 | 行为 |
| --- | --- |
| 服务端 Casdoor | 用户缓存 60s（LRU + 单飞），失败熔断 30s |
| 服务端身份 | 每次查库（主键/唯一索引，微秒级） |
| 插件决策 | 按 UUID 缓存，TTL 由响应里的 `cache_ttl_seconds` 决定（默认 60s） |
| Casdoor 故障 | 有缓存用缓存；冷用户按 `CCNR_DATA_AUTH_FAIL_MODE`（默认 deny） |
| CCNR-Data 故障 | 插件用缓存；新登录按 `fail_open`（默认 false = 拒绝）；在线玩家不掉线 |

拒绝消息必须是人话，例如「账号尚未绑定，请先完成 CCNR Pass 登录与 MC 账号绑定」。

## 5. 统计口径

| 指标 | 定义 | 来源 |
| --- | --- | --- |
| 在线 | `ended_at IS NULL AND last_seen_at >= now - 180s` | `proxy_sessions` |
| 会话数 | 时间窗内 `started_at` 的数量 | `proxy_sessions` |
| 时长 | 每个会话与查询窗口求交后求和，跨窗口裁剪 | `proxy_sessions` |
| 独立玩家 | 窗口内出现过的 `player_uuid` 去重 | `proxy_sessions` |
| 登录失败 | `LOGIN_DENIED` 事件数（按原因分组） | `proxy_events` |
| 分服在线峰值 | 5 分钟桶内的会话并发最大值 | 实时计算 |

- 心跳 60s **只更新** `last_seen_at`，不写事件表；因此 100 人在线 = 1.7 次写/秒，而不是 100 行/分钟。
- 代理崩溃留下的孤儿会话：后台 worker 每 60s 把 `last_seen_at < now - 180s` 的会话收尾（`end_reason='timeout'`）。
- 轮换：`proxy_events` 30 天、`proxy_sessions` 365 天（仅已结束）、过期规则 90 天。
  **业务表（`players` / `settlements` / `proxy_sessions` 未结束行）永不自动清除。**

## 6. 身份投影与平台账号

- 平台账号绑定单独一张表：`account_links(user_id PK, casdoor_user_id UNIQUE, source, linked_at, updated_at)`。
  写入方是 `BindAccountLink` 与设备码 `LINK` 轮询器（`source=PASS`）；bot 只通过
  `GetAccountLink` / `BindAccountLink` / `DeleteAccountLink` 读写，不落本地库。
- 表：`player_identities(player_uuid PK, username, username_lower UNIQUE, casdoor_user_id, source, linked_at, updated_at)`。
- 写入方：管理导入（P1）、bot 绑定（P4 之后）、皮肤站登录回调（P4）。
- 设备码登录写入的 `source` 为 `PASS`；`casdoor_user_id` 存 Casdoor `get-user` 的 `owner/name` 形态（如 `ccnr/bananaxiao2333`）；旧数据里的裸 UUID 会在查询时回退一次用户列表匹配。
- 一个 UUID 只能对应一个 Casdoor 用户；换绑必须显式 `overwrite=true` 且记审计。
- 用户名改名时覆盖 `username/username_lower`，旧值进审计。

## 7. 配置

所有运行时配置走 `CCNR_DATA_*` 环境变量，见 [`.env.example`](../.env.example)。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `CCNR_DATA_DATABASE_URL` | 由 `DB_FILE` 推导 | SQLAlchemy URL |
| `CCNR_DATA_DB_FILE` | `var/ccnr-data.db` | 仅用于推导 URL / 兼容旧配置 |
| `CCNR_DATA_HTTP_BIND` | `127.0.0.1:8082` | 健康与指标端口 |
| `CCNR_DATA_CLIENT_TOKENS` | 空 = 不鉴权 | JSON，例如 `{"proxy":"...","bot":"..."}` |
| `CCNR_DATA_CASDOOR_ENDPOINT` | 空 | Casdoor 根地址 |
| `CCNR_DATA_CASDOOR_CLIENT_ID/SECRET` | 空 | M2M 应用凭据 |
| `CCNR_DATA_CASDOOR_ORGANIZATION` | `ccnr` | 用户所属组织 |
| `CCNR_DATA_AUTH_FAIL_MODE` | `deny` | Casdoor 冷用户故障策略 |
| `CCNR_DATA_HEARTBEAT_TTL_S` | 180 | 在线判定窗口 |
| `CCNR_DATA_PROXY_EVENT_RETENTION_DAYS` | 30 | 代理事件轮换 |
| `CCNR_DATA_SESSION_RETENTION_DAYS` | 365 | 已结束会话轮换 |

## 8. 运维

- 升级：`make db-upgrade`；旧库先 `make db-adopt`（校验 v1 后 stamp + upgrade）。
- 健康：gRPC 标准 Health（`""` 与两个服务名）；HTTP `/healthz` 额外报告 Casdoor 熔断与最近上报时间。
- 指标：`authorize_total{decision,reason}`、`authorize_latency_seconds`、`report_total{kind}`、
  `sessions_online`、`casdoor_requests_total{result}`、`casdoor_circuit_open`。
- 排障顺序：先看 `/healthz`（Casdoor/DB）→ 看授权指标里的 deny 原因分布 → 看 `LOGIN_DENIED` 事件。

## 9. 失败模式

见 [ADR-0003](adr/0003-velocity-access-and-telemetry.md) 与 [ADR-0001](adr/0001-central-control-plane.md)。
一句话：**代理永远不因为控制面故障而卡住在线玩家；新登录默认拒绝并给出可读原因。**

## 10. 分阶段

| 阶段 | 内容 |
| --- | --- |
| P0 | 核对 Velocity 版本 / 登录链路 / UUID 来源 / Casdoor 角色名 |
| P1a | SQLAlchemy + Alembic 替换裸 SQL（现有 RPC 行为不变） |
| P1b | `control.v1` + 身份/准入/统计/查询 + HTTP 边缘 |
| P2 | Velocity 插件遥测（shadow 模式） |
| P3 | 打开准入（先 log 后 enforce） |
| P4 | 查询接入 bot、皮肤站回调、文档收尾 |
